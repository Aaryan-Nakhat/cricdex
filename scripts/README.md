# scripts

Command-line entry points for the offline pipeline. Run them from the repo root with `uv run python
scripts/<name>.py …`; add `--help` to any of them for the options. Most day-to-day use goes through
`cricdex data ingest …`, `make refresh COLLECTION=<c>` (download → ratings → metrics → site data) or
`make refresh-all` (every exported league, one export at the end), which call these for you. The
league list itself is [`config/leagues.toml`](../config/leagues.toml) — see
[`docs/LEAGUES.md`](../docs/LEAGUES.md).

| Script | What it does | Example |
|---|---|---|
| `ingest_cricsheet.py` | Downloads a Cricsheet collection (which zip(s) is set in the league registry, [`config/leagues.toml`](../config/leagues.toml)), writes Parquet and loads the DuckDB tables (`matches_`, `innings_`, `balls_`, `wickets_`, `replacements_`, `match_players_`, `players_<col>`, plus `ingest_meta`), then merges venue names. `all` ingests every exported league; `list` prints the registry. SMAT (`indian_domestic_male`) is one more collection, from Cricsheet's `sma_json.zip`. | `ingest --collection ipl --force` · `all --force` · `list` |
| `rebuild_all.sh` | Rebuilds everything for every exported league in the registry: ingest → People Register → ratings for all → metrics for all → one export (only after every league is refit). Resumable (markers in `data/.rebuild_state`, log in `data/rebuild.log`); `--fresh` starts over; `--from ratings` keeps the ingested data and People Register and refits ratings → metrics → export (`--from metrics` / `--from export` start later); `LEAGUES="ipl psl"` limits the refit. Multi-hour — on Windows run it as a scheduled task. | `bash scripts/rebuild_all.sh` |
| `auction_check.py` | Sanity-checks the IPL mega auction on the exported data (same simulator as the website): purse used per team, squad sizes, price spread and the top of the pool. Run it after a rebuild or a pricing change. | `--trials 300` |
| `ingest_people.py` | Downloads the Cricsheet People Register (`people`, `people_names`). | `--force` to refresh |
| `ingest_wikidata.py` | The older bulk Wikidata path (SPARQL, rate-limited from datacenter IPs). The entity-API path is `cricdex data ingest wikidata`. | — |
| `enrich_taxonomy.py` | Tags each player's role, bowling type, batting slot, hand and country with an LLM via LiteLLM (any provider, set in `.env`); cached in `data/curated/player_taxonomy.json`, shown as "AI-classified". Only players missing from the cache are queried. | `--batch 20` |
| `compute_metrics.py` | Computes the leaderboards into `data/metrics/<metric>_<col>.json`; `all` runs NGI, the nine context metrics and the two fielding boards; `ngi-diagnostics` prints the win-probability checks (isotonic vs smooth calibration, monotone constraints, era features on a later season, in-sample vs out-of-fold NGI). | `all -c ipl` · `ngi-diagnostics -c ipl` |
| `scout_rate.py` | Fits the dismissal-aware Bayesian ratings into `data/metrics/scout_ratings_<col>.json` (ADVI by default, `--sampler nuts` for the exact run; `--variant legacy` fits the earlier model without context terms) and the fitted context (season / phase / innings levels, batting-slot means) into `scout_context_<col>.json`. | `-c ipl --sampler nuts` |
| `export_site.py` | Cooks everything into the static JSON snapshot in `site/public/data/` that every surface reads (leaderboards and time windows, profiles, auction pool, scout index, Keep or release's `keep.json`, matchups, …), plus `leagues.json` (the league registry the web app reads labels, Scout pools and each league's fitted translation from). | `-c ipl` (blank = every exported league in the registry) |
| `ipl_squad_salaries.py` | Adds each IPL squad player's salary (`salary_cr`), how he was acquired (retained / trade / auction / replacement), nationality and `overseas` flag and Cricsheet id to `data/curated/ipl_squads_2026.json`, from Wikipedia's 2026 personnel-changes page (CC BY-SA), then applies the moves since the season (trades, retirements) from the 2027 page. Hand edits are kept unless `--force`; unmatched players are listed. Feeds Keep or release (`cricdex keep`). | `--force` · `--wikitext page.wiki` |
| `ipl_auction_history.py` | Every IPL auction 2008–2026 from Wikipedia's per-season personnel pages (CC BY-SA; pages cached in `data/curated/ipl_auction_pages/`, pinned to a revision): sold lots (base price, price, buyer, previous team, set, RTM) and retentions with salaries, US$ years converted at the Fed H.10 rate, each matched to a Cricsheet id → the hand-editable `data/curated/ipl_auction_history.json` (rows with `"edited": true` survive a re-parse). | `--fetch` |
| `ipl_captains.py` | IPL and international captaincy from Wikipedia (CC BY-SA; each franchise's captains table filled in from the IPL captains list; men's Test / ODI / T20I captains of 11 Test nations; pages cached in `data/curated/ipl_captain_pages/`) matched to Cricsheet ids → the hand-editable `data/curated/ipl_captains.json`, read by the price model and the export (Captain badges). | `--fetch` |
| `league_translation_fit.py` | How a rating in another league carries over to the IPL, per league and role (METHODOLOGY §6d). `pairs`: every league and IPL rating as of each IPL season 2015–2026 (the backtest cache's fits) and every IPL season's observed values (~1 min). `fit`: hierarchical NUTS fit, rolling validation 2022–24 over five declared candidates, one test on 2025–26 against the old discounts and no translation (level calibration), ship to `config/league_translation.json` (~15 min). `reality`: the reality table. Report: `data/metrics/league_translation_ipl.json`. | `pairs`, then `fit`, then `reality` |
| `ipl_price_model.py` | The market-price model (METHODOLOGY §6b). `fits`: the IPL re-fitted before every auction date (cached under `data/metrics/.backtest_cache/<model version>/v2/ipl_auction<season>_…`, resumable, ~45 min). `fit`: auction-time features, P(bought) logistic + Huber ln(price / purse), out-of-time evaluation (train ≤ 2024, test 2025 + 2026) against the old curve, refit and export to `config/price_model.json`. | `fit --first 2018 --kind huber --retentions plain --report eval.json` |
| `form_forecast.py` | Form forecast (METHODOLOGY §11): each IPL player's value over the next three seasons. `fits`: the ratings at every season end, per ADVI seed (the price model's cache, same file names; resumable). `backtest`: projections from data through 2021 / 2022 / 2023 scored on 2022-2026 against four baselines, 3 seeds → `data/metrics/forecast_backtest_ipl.json`. `build`: trains on every season pair and projects every active player from the current ratings → `data/metrics/forecast_ipl.json`. `export`: the site's `ipl/forecast.json` (read by the profile and `cricdex forecast`). | `fits --seeds 42` · `backtest` · `build` · `export` |
| `playing_time_fit.py` | The playing-time model (METHODOLOGY §6c), each piece under the frozen protocol (chosen on seasons ≤ 2024, tested once on 2025–26): `usage` (who played, where he batted, his balls), `balls` (expected balls a match), `repl` (the replacement curves, continuous in batting position and in balls bowled, fitted on minimum-price buys; since 2026-10-26, ROADMAP I17a), `play` / `free` (P(plays) in a squad / as a free agent), `ship` (writes `config/playing_time_model.json`), `asof-contrib` (contributions as of every auction, for the price and Keep backtests), `buy` (P(plays) of an auction buy in the squad that bought him) and `value` (a buy's expected value calibrated on real buys), both since 2026-10-27. Results in `data/metrics/playing_time_ipl.json`; caches under `data/metrics/.playing_time/` (delete `play_rows.pkl` and `fa_rows.pkl` after changing the replacement curves). | `usage` · `balls` · `repl` · `play` · `free` · `ship [--before 2026-12-16]` · `asof-contrib` |
| `rating_drift_fit.py` | The time-aware rating (METHODOLOGY §4b; `scout/ratings/drift.py`, since 2026-10-27): a state-space model of every player's season values in every pool league (a random walk and an aging curve per group, with a selection model so the players who stopped don't flatter the curve). `obs`: season values per league and calendar year, and up to each auction date (~4 min, cached in `data/metrics/.drift/`; a league with new matches is recomputed from its last year). `validate`: seven declared candidates walk-forward on 2019–2024, chosen by next season's contribution per match (~1.5 h). `test`: the chosen one, fitted to 2024, once on 2025–26. `ship`: `config/rating_drift.json` (`model`, and `model_le2024` for the other protocol runs). `curves`: one fit's parameters. Report: `data/metrics/rating_drift_ipl.json`. After a new `ship`, rerun `playing_time_fit.py` from `repl` (delete `minbuy_pairs.pkl`, `play_rows.pkl`, `fa_rows.pkl`, `asof_contrib.parquet`). | `obs` · `validate` · `test` · `ship` |
| `inactivity_gap.py` | The evidence for the auction pool's activity rule (METHODOLOGY §7): of every spell without a match in any covered league (the playing-time usage table), the share after which the player played anywhere, and in the IPL, again, for gaps of 1–4 years, all players and former IPL players → `data/metrics/inactivity_gap_ipl.json` (~1 min; needs `playing_time_fit.py`'s usage cache). | `[--last-start 2021-09-30]` |
| `bidplan_backtest.py` | Replays the 2025 mega and 2026 mini auctions for Bid plan (METHODOLOGY §12): walk-forward values and price models (only what was known before each auction), real retentions and purses, each team's plan played against the real prices and scored on the next season, against what the team really bought; top-10 targets bought; calibration of P(≤ max bid). Pool = sold lots + unsold alternatives (the P(bought) risk set); rivals calibrated. Resumable per team, ~35 min (run as a scheduled task on a laptop). Needs `ipl_price_model.py fits`. | `--work DIR --trials 200 --out report.json` |
| `auction_calibrate.py` | Calibrates the auction simulator's bidding to real auctions (AUCTION_MATH Part 3b): replays 2022 (mega), 2023 and 2024 (mini) with all ten teams bidding, grid-fits the level per auction type, the value curve, the demand-shock sd and the last-price weight (market tightness on), and tests out of time on 2025 and 2026 (log bias, MAE, rank correlation, coverage of the simulated range, the dearest simulated lots). The chosen numbers go into `auction.py` ⇄ `auction.ts` by hand. ~1 h. | `--work DIR --trials 40 --out calib.json` |
| `records.py` | Records and On This Day from the DuckDB. | `list` · `top fastest_fifty -c ipl` · `today` · `all` |
| `style_twin.py` | Nearest-neighbour style twins for one player. | `"MS Dhoni" -c ipl` |
| `backtest_ratings.py` | Walk-forward check: fit before each IPL season, compare with that season, against career averages (Spearman, 3 ADVI seeds) and score every ball of the season (held-out log-likelihood); `--compare legacy` runs the earlier model alongside. | `-c ipl --seasons 2021-2026 --compare legacy` |
| `backtest_newcomers.py` | Rates IPL newcomers from the other auction-pool leagues only (every `auction_pool` league in the registry except the IPL; the published run used BBL / SA20 / CPL / Blast / SMAT) and scores their first IPL season. Leagues are translated onto the IPL (the fitted league translation) and pooled by precision; the raw baseline gets the same league centring and translation; 3 ADVI seeds; all six tests with bootstrap and Holm-adjusted p; a 30 / 120-ball playing-time sensitivity check. Fits are cached in `data/metrics/.backtest_cache/` and run in parallel with `--jobs`. | `--seasons 2014-2026 --jobs 2` |
| `media_data.py` | Computes every number the README visuals show (the default mega auction, Keep or release for one team, Bid plan's live 2027 sheet for one team, Scout for one player, ratings, NGI leaders, backtests, Bid plan's replay) from the exported site data with `cricdex.web_parity`, into `docs/media/src/data.js`. Run it before the two renderers. | `uv run python scripts/media_data.py [--keep-team RCB] [--bidplan-team RCB] [--scout "Jasprit Bumrah"]` |
| `render_video.py` | Renders the README video from `docs/media/src/*.html`. | `uv run --with playwright python scripts/render_video.py docs/media/src/hero.html --out docs/media/hero` |
| `render_images.py` | Renders the README images from `docs/media/src/img-*.html`. | `uv run --with playwright python scripts/render_images.py` |

What each model does and why: [`docs/METHODOLOGY.md`](../docs/METHODOLOGY.md). The backtest results are in
[§8](../docs/METHODOLOGY.md#8-does-it-predict-the-backtest).
